# i18n

The renderer uses [vue-i18n](https://vue-i18n.intlify.dev/) (Composition API);
the Electron main process uses a tiny shared translator in
`apps/desktop/src/contracts/i18n/index.ts`. Both read the **same catalog** so
the renderer and the OS-level chrome (app menu, tray, window titles, native
file dialogs) never drift.

## Catalogs

- `apps/desktop/src/contracts/i18n/en.ts` — the English catalog (single source
  of truth; nested by feature, `as const`).
- `apps/desktop/src/contracts/i18n/de.ts` — German. ⚠️ **machine-translated,
  unreviewed** — see below.
- `apps/desktop/src/renderer/src/i18n/locales/pseudo.ts` — the dev pseudo
  locale, auto-derived from `en` via `toPseudo` (wraps every string in `⟪…⟫`).
  Hand-edit `en.ts`, never `pseudo.ts`.

The shared module exports `LOCALES`, `Locale`, `DEFAULT_LOCALE`, `toPseudo`,
and `translate` (a dependency-free translator the main process uses directly;
the renderer wraps the catalogs in vue-i18n). `Locale` also types the
`AppState.locale` field mirrored to `app-state.json` so the main process can
read the active locale at boot.

## Conventions

- Components: `const { t } = useI18n();` (or `tm` for array messages).
- Non-component `.ts`: `import i18n from "@/i18n"; const t = i18n.global.t.bind(i18n.global);`.
- Plurals: vue-i18n v11's array form `["one","many"]` is a **NOOP** — use the
  `|`-separated string form with `t(key, n)` (e.g.
  `contextMenu.moveToTrashConfirm`). `{n}` auto-binds to the count.
- Config-array labels (settings groups, route titles, command titles) are
  stored as **key strings** and resolved at render with `te(key) ? t(key) : key`.

## Switching locale at runtime

`setLocale(locale)` (renderer) switches vue-i18n, persists to `localStorage`,
mirrors to the main-owned `app-state.json`, and notifies the main process
over the `app:set-locale` IPC. The main process rebuilds its app menu + tray
context menu in the new language without a restart (window titles are set at
creation; the renderer overrides `document.title` for content windows).

## Adding a locale

1. Copy `en.ts` → `<locale>.ts` and translate every leaf (preserve `{param}`
   placeholders and `|`-plural forms; translate array leaves element-wise).
2. Append the locale code to `LOCALES` in `contracts/i18n/index.ts` and to the
   `z.enum` in `appStateSetInput` (`contracts/router.ts`).
3. Import the catalog in `contracts/i18n/index.ts` (`export { default as <code> }`)
   + register it in the renderer `i18n/index.ts` `messages` map and the main
   `i18n.ts` `messages` map.
4. Add a label in `settings.language.*` (en + the new locale) and a branch in
   `LanguageSection.vue`.
5. Settings → Language → **Pseudo (dev)**, sweep every surface — any bare
   English is a missed `t()`.

## `.po` round-trip (translator workflow)

`npm run i18n:po` is a no-dependency dev tool for translating a catalog via
gettext `.po` files (so a translator doesn't edit TypeScript):

```sh
npm run i18n:po export en     # contracts/i18n/po/en.po  — English reference
npm run i18n:po export de     # contracts/i18n/po/de.po  — entries carry an `# en:` reference
# translator edits the msgstr values in de.po
npm run i18n:po import de     # regenerates contracts/i18n/de.ts from de.po
```

`msgid` is the dotted catalog key; array leaves use `key[0]`…`key[n]`. Empty
`msgstr`s import as sparse (omitted) keys, which fall back to English.

## ⚠️ German strings are unreviewed

`de.ts` was machine-translated and has **not** been reviewed by a native German
speaker. Before any public release, run the `.po` round-trip through a human
translator: `export de` → review `de.po` → `import de`.
